WORKSTREAM 0 — THE DEFECT (Phase 1 §D, ship-blocking; built FIRST)
------------------------------------------------------------------
migrate_legacy_schema's invoice-line backfill fabricated a
"Legacy zero-value invoice placeholder" line (source 'extra' /
'legacy-zero') on every invoice with no source tickets/work orders, on
every request. That defeated record_payment's lineless-invoice guard in
the live path: a split payment whose second leg targeted a lineless
invoice POSTED instead of rolling back whole, and issued a real
overpayment credit memo against an invoice with no real lines.

History, established before fixing: the backfill's legitimate purpose
is snapshot lines for pre-line-era invoices, synthesized from their
real source tickets (ticket_money) and work orders (bill_amount) —
that part is honest and is PRESERVED unchanged. The placeholder
fallback served no source document; it exists identically in all three
trees on this VM (phone 'l', merged ancestor, web fixround) — inherited
code, not a phone-side invention. Nothing else in the codebase reads
the 'legacy-zero' signature: no display filter, no report exclusion —
once inserted it rendered and printed as a real line.

Fix (engine_migrations.py):
- The zero-placeholder fallback insert is REMOVED. An invoice with no
  source tickets/work orders stays lineless: not payable, totals $0.00,
  prints no lines, until real lines exist (its own editor writes
  'quick' lines directly; ticket/WO billing writes source lines).
- The same migration RETRACTS previously fabricated lines by their
  exact migration-only signature (source_type='extra' AND
  source_id='legacy-zero'). Operator "extra" lines carry
  source_id 'extra-<line_id>' and can never match.

3. IN-PLACE CLASS SWITCH (engine save_asset, the asset form):
   the editor's Designation control changes an existing asset's
   class in place — no sell-and-re-add. A change is an audited
   event in the Done record (who/when/from→to, e.g. "Asset
   GEN-101: class Fleet → Stock"), clerk stamped from the desk
   session by the handler, never a posted field. A save that
   does not carry the field leaves the class standing.

   Jason's look): while the asset is out on a live ticket
   (Reserved / Dispatched / On Rent / Standby — the set the form
   already locks the unit number against), class and status
   changes are REFUSED with the reason stated ("… is out on
   ticket T-#### — class and status cannot change until it
   returns"). A Quoted ticket does not hold the switch (a
   proposal, not possession; conversion re-checks at the
   engine), and neither does an open work order.

   De-listed — a closed set on the same editor surface, switched
